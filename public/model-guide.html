Choosing a VLM for Robot Tasks

Start with the capability your task needs, then check whether the agent can satisfy the complete goal within your observation, tool, and time constraints.

Based on the 5 October 2026 author manuscript, submitted for arXiv v2. Experimental results are unchanged from v1. Read Table 2 or download all 56 comparison scores.

Which Frontier VLM Performs Best on Robot Tasks?

In this evaluation, GPT-6 Astra has the highest aggregate Task Planning and baseline Manipulation success: 80.3% and 41.8%, compared with Claude Fable 5.1's 63.7% and 24.7%. Astra also has the lowest pose errors and highest contact validity. These results favor Astra on this task mixture; they do not establish a universal ranking across robot platforms, tools, or deployment conditions. Main results, Section 4.2.

The best choice changes with the metric. Gemini 3.8 Flash has the lowest numerical Spatial Reasoning AbsRel (0.161, versus Astra's 0.213). Qwen 3.8 Max is close to Astra on Spatial Pass@1 (68.9% versus 69.4%), and Fable is close on functional-region mask overlap (0.284 versus 0.286 IoU). Small mean differences should be read alongside run variation and task-level results. Full seven-model comparison.

GPT-6 Sol reaches 44.6% Planning and 19.8% Manipulation success. The two open-source Qwen models also differ by capability: Qwen 3.5 397B-A17B has higher Spatial Pass@1 than Qwen 3.5 27B (50.6% versus 48.0%), while the smaller model has higher Manipulation success (11.0% versus 9.9%). Model size alone does not order these observed scores. Table 2.

Does Spatial Competence Guarantee Manipulation Success?

No guarantee follows from these results. The study compares capability profiles and diagnoses task outcomes; it does not establish a statistical predictor from spatial scores to manipulation success. Accurate geometric estimates, valid contacts, or a near-correct trajectory can coexist with an incorrect endpoint or an unsatisfied final goal. Geometric and spatial diagnostics.

All seven agents completed 0 of 5 evaluated BEHAVIOR-1K tasks under limits of 180 minutes per trial, 24 model rounds, 256 tool calls, 640k tokens, and 1,000 environment control steps. Success requires all native task conditions. All seven also completed 0 of the eight HumanCLAW sitting tasks, whose limits include 180 minutes per episode, 101 code rounds, 100 environment steps, 400 primitive calls, and 2M tokens (11,000-second outer task timeout). These are specific evaluated subsets. Zero success does not imply that every episode timed out. Sitting diagnostics and manipulation results; execution limits.

The practical question is whether local skills produce the required final state within the available resources. The paper therefore reports complete-task success separately from intermediate progress. Source-native helpers remain available; the baseline adds no specialist perception or verification pipeline. Richer visual feedback and multi-round review are separate supplementary comparisons. Further investigations.

How Should These Results Be Compared or Reproduced?

Keep observations, tools, and budgets explicit. The main experiment uses a minimal harness with source-native observations and helpers. Limits vary by source and execution configuration; there is no single universal budget. For Manipulation, Baseline and RGB-expanded share per-source limits, while RGB-expanded supplies current RGB views at each decision. See Appendix B and Appendix E.1.

Match repetitions and denominators. Non-tracing Geometry, Spatial Reasoning, and Affordance use five runs per case for six models and three for Fable. Tracing, Task Planning, and Manipulation have one reported episode per assignment. Continuous errors pool valid estimates; binary success retains assigned cases. The Manipulation success denominator is 182 binary tasks, while the 183-case inventory includes one continuous-reward task. Scoring and repetition accounting.

Retain the actual inference configuration. Fixed-input and Planning configurations use temperature zero. On the CLI interface, reasoning effort is maximum for Sol and high for Astra and Fable; API requests omit this parameter. Fixed-input profiles include different response ceilings and extended case budgets. Manipulation uses separate request and execution limits, including a 3,600-token response ceiling and 12-minute request timeout. Use the full configuration tables rather than assigning one setting to every task. Model settings; additional configurations; Manipulation settings.

Start with the evaluation harness and quick start, the 1,000-case dataset, and its pinned release revision. The summary CSV contains the paper's comparison scores, not per-case predictions; per-model reproduction reports remain on the repository roadmap.
