01 / Common Tasks

Model Diversity Does Not Remove the Shared Failure Set.

Astra completes 126 of the 157 Planning tasks; Gemini 4 Argon completes 110. Across all ten models, at least one succeeds on 142 tasks: 16 more than Astra alone. Fifteen tasks remain incomplete for every model, while eight are completed by all ten. Model diversity expands coverage but leaves a shared failure set.

The next evaluation target is the shared failure set, alongside the tasks on which models complement one another. The 15 common failures comprise two ALFRED tasks, two ALFWorld tasks, nine HumanCLAW tasks and two ScienceWorld tasks. These are observed outcomes on the shared task assignments; the union is an after-the-fact coverage count, not a tested routing policy.

02 / Resources

Unfinished Tasks Consume Most Tokens.

Median Planning episode duration ranges from 57.1 seconds for DeepSeek-1017 to 280.7 seconds for Sol. Completion rates differ at the same time, so a short run can reflect either efficient success or early failure. The source filter on the project page shows these quantities together.

Between 55.5% and 86.9% of each model’s recorded tokens are spent on unsuccessful episodes. Even Astra, which completes 80.3% of the assignments, spends 55.5% of its recorded tokens on the 31 that it does not complete. A failed Astra task uses 5.1× as many tokens as a successful task on average (591,162 vs. 116,435). The cost of unresolved tasks is therefore much larger than their share of the task count.

03 / Recovery

Recovery Must Change the Task State.

Gemini 4 Argon completes 16 of 28 Planning episodes containing an execution error; Opus 5.5 completes 48 of 105. These counts separate how often a model encounters errors from whether it can recover and finish. Errors include malformed code and rejected API use.

The same Archaeology Dating task makes the distinction visible. Gemini 4 Argon encounters an error in round two, resumes measurable progress in round three and completes in round eight. Opus 5.5’s first two rounds fail before an environment action. It then collects tools, excavates the sites, reads artifact ages and places the flag at the oldest site, reaching the native score of 1.0 in round seven. DeepSeek-1017 reaches 0.5 by round five, then its last three rounds end in code errors with no further environment steps.

Recovery is useful when it changes the task state. A revised response by itself is not evidence that the goal is any closer.

Early Progress Rarely Reaches the Goal.

Across ten models on ten CALVIN sequences each, 60 of 100 episodes reach the first goal, but only nine finish all five. Gemini 4 Argon completes four sequences, GPT-6 Astra three, and Claude Opus 5.5 and DeepSeek 4.1 Flash-1017 one each.

The recovery gap spans models. DeepSeek 4.1 Flash-1017 resumes code in all ten episodes with an execution error; Claude Opus 5.5 and Claude Fable 5.1 each resume in all nine. Only one, one, and zero of those episodes finish, respectively. Across all ten models, 62 of 65 error episodes resume execution and only three complete the task. Clearing an execution error leaves the remaining subgoals to be solved.

04 / Physical Progress

A Valid Action Is Not a Completed Subgoal.

On CALVIN sequence 0526, Opus 5.5 completes five subgoals using 338 action submissions, 18 model calls and 229.4 seconds. Gemini 3.8 uses 501 action submissions and 464 state observations, yet finishes with zero of five subgoals after 36 calls and 796.5 seconds. Its final stop is the token budget. Gemini 4 Argon completes all five goals with 475 action submissions, 408 state observations, 18 model calls and 351.9 seconds. The current-subgoal queries show Opus 5.5 advancing through retrieval, storage, stacking and the light switch; Gemini 3.8’s retained queries remain on the first lifting goal.

ALFRED makes the final conditions explicit: Gemini 4 Argon satisfies all three conditions for cleaning a soap bar and placing it in the bathtub in six rounds; DeepSeek-1017 ends at one of three after eight rounds. On RoboCasa’s left-drawer task, Gemini 4 Argon completes in 13 rounds despite an error in round ten, while Sol reaches its 24-round ceiling without the required final state.

Count verified changes in the task state, then relate them to actions, observations and elapsed time. This separates purposeful progress from activity that leaves the goal unsatisfied.

Which budget actually stopped the episode?

In the selected BEHAVIOR-1K toolbox task, none of the ten models completes the native goal. Gemini 4 Argon uses 603,393 recorded tokens before the next round is blocked by the 640,000-token limit, after 37.5 minutes of a 180-minute ceiling. On charger insertion, it also reaches a token guard: after 23 native steps the final goal distance is still 15.9 cm. More wall time alone would leave these stopping limits in place.

Evidence and Definitions

From Recorded Outputs to Reproducible Counts.

All comparisons use ten models: 157 adopted Gemini 4 Argon Planning reports join the original 1,413 episodes. Earlier retries are excluded. Gemini 4 Argon’s time, usage and error counts come from those same adopted reports; 109 gallery executions are matched to the new logs by report hash. All report SHA-256 hashes were checked against the supplied log manifest. Native task identity was checked separately for the HumanCLAW wrappers whose model-specific canonical names differ. Completion counts reproduce the adopted main-table Planning results.

Time is reported episode wall time, or the campaign duration where supplied, falling back to the last recorded loop time. It includes reported setup and environment interaction, so it is not model inference latency. IQR is the 25th–75th percentile. Token totals use recorded input plus output usage. Missing usage is excluded: coverage is shown for every model. Failure token share is the sum in unsuccessful episodes divided by the sum in all episodes with recorded usage. Recovery means native final success after an earlier recorded execution error; budget guards and timed-out rounds are excluded from that error count.

The video explorer contains 46 same-task groups, 460 episodes and 6,640 recorded rounds. Its Manipulation examples retain their recorded configurations; the main table aggregates the adopted evaluation assignments. The protocol audit distinguishes observation schedules and execution ceilings. Per-episode settings, stop limits and source hashes accompany each trace. Native tool events are matched to round completion timestamps; any events without a close timestamp match remain separately available in the trace. Video excerpts and saved-observation sequences retain their own playback clock.
