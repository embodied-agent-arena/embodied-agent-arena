01 / Common Tasks

Model Diversity Does Not Remove the Shared Failure Set.

Astra completes 126 of the 157 Planning tasks; Gemini 4 Argon completes 110. Across all ten models, at least one succeeds on 142 tasks: 16 more than Astra alone. Fifteen tasks remain incomplete for every model, while eight are completed by all ten. Astra and Gemini 4 Argon alone cover 137 tasks, recovering 11 of the 16 extra successes available across the ten-model union. Complementarity is concentrated, while a shared failure set remains.

The next evaluation target is the shared failure set, alongside the tasks on which models complement one another. The 15 common failures comprise two ALFRED tasks, two ALFWorld tasks, nine HumanCLAW tasks and two ScienceWorld tasks. Combined coverage counts a task once when at least one model succeeds.

02 / Resources

Unfinished Tasks Consume Most Tokens.

Median Planning episode duration ranges from 57.1 seconds for DeepSeek-1017 to 300.0 seconds for Qwen 3.8 Max. Completion rates differ at the same time, so a short run can reflect either efficient success or early failure. The source filter on the project page shows these quantities together.

Unsuccessful episodes consume 55.5–94.3% of each model’s recorded tokens, but two different patterns produce this cost. For the strongest planners, failed-token expenditure concentrates in prolonged physical interactions. HumanCLAW accounts for 13 of 157 tasks yet 81.7% of Astra’s failed-token expenditure. Removing it lowers the failed-token share from 55.5% to 19.4% for Astra and from 64.0% to 33.5% for Gemini 4 Argon. Its larger budgets permit repeated attempts at body control and sitting, even while the required state remains unmet.

For the other models, failures extend across ordinary procedures. Outside HumanCLAW, unsuccessful episodes still consume 55.3–67.8% of recorded tokens for the other closed-weight models and 73.6–85.8% for the open-weight VLMs. On the same ScienceWorld animal-transfer task, DeepSeek spends three of eight decision rounds inspecting state and stops with 89 environment steps unused. Opus identifies the blue-jay egg as the requested animal and completes the procedure. The difference concerns resolving the next task requirement, rather than the availability of more environment actions.

03 / Recovery

Recovery Must Change the Task State.

Gemini 4 Argon completes 16 of 28 Planning episodes containing an execution error; Opus 5.5 completes 48 of 105. These counts separate how often a model encounters errors from whether it can recover and finish. Errors include malformed code and rejected API use.

The same Archaeology Dating task makes the distinction visible. Gemini 4 Argon encounters an error in round two, resumes measurable progress in round three and completes in round eight. Opus 5.5’s first two rounds fail before an environment action. It then collects tools, excavates the sites, reads artifact ages and places the flag at the oldest site, reaching the native score of 1.0 in round seven. DeepSeek-1017 reaches 0.5 by round five, then its last three rounds end in code errors with no further environment steps.

Recovery is useful when it changes the task state. Successful correction restores the missing prerequisite and enables the next required action.

Early Progress Rarely Reaches the Goal.

Across ten models on ten CALVIN sequences each, 60 of 100 episodes reach the first goal, but only nine finish all five. Gemini 4 Argon completes four sequences, GPT-6 Astra three, and Claude Opus 5.5 and DeepSeek 4.1 Flash-1017 one each.

The recovery gap spans models. DeepSeek 4.1 Flash-1017 resumes code in all ten episodes with an execution error; Claude Opus 5.5 and Claude Fable 5.1 each resume in all nine. Only one, one, and zero of those episodes finish, respectively. Across all ten models, 62 of 65 error episodes resume execution and only three complete the task. Clearing an execution error leaves the remaining subgoals to be solved.

04 / Physical Progress

A Valid Action Is Not a Completed Subgoal.

In the supplementary RGB-expanded CALVIN 0526 comparison, Opus 5.5 completes five subgoals using 338 action submissions, 18 model calls and 229.4 seconds. Gemini 3.8 uses 501 action submissions and 464 state observations, yet finishes with zero of five subgoals after 36 calls and 796.5 seconds. Its final stop is the token budget. Gemini 4 Argon completes all five goals with 475 action submissions, 408 state observations, 18 model calls and 351.9 seconds. The current-subgoal queries show Opus 5.5 advancing through retrieval, storage, stacking and the light switch; Gemini 3.8’s retained queries remain on the first lifting goal.

ALFRED makes the final conditions explicit: Gemini 4 Argon satisfies all three conditions for cleaning a soap bar and placing it in the bathtub in six rounds; DeepSeek-1017 ends at one of three after eight rounds. On RoboCasa’s left-drawer task, Gemini 4 Argon completes in 13 rounds despite an error in round ten, while Sol reaches its 24-round ceiling without the required final state.

Count verified changes in the task state, then relate them to actions, observations and elapsed time. This separates purposeful progress from activity that leaves the goal unsatisfied.

Which budget actually stopped the episode?

In the selected BEHAVIOR-1K toolbox task, none of the ten models completes the native goal. Gemini 4 Argon uses 603,393 recorded tokens before the next round is blocked by the 640,000-token limit, after 37.5 minutes of a 180-minute ceiling. On charger insertion, it also reaches a token guard: after 23 native steps the final goal distance is still 15.9 cm. More wall time alone would leave these stopping limits in place.

05 / Region Grounding

Precise Outlines Still Need the Right Target.

Astra leads rotation estimation and Planning; Gemini 3.8 Flash has the lowest numerical spatial error; Gemini 4 Argon leads Spatial Pass@1 and both region-overlap metrics; Opus 5.5 has the highest reported Manipulation success. These rank changes make a single proxy inadequate for selecting an embodied generalist.

Evaluation Protocol

Tasks, Outcomes, and Resource Use.

Ten models are evaluated on the same 157 Planning tasks, with one evaluated episode per model and task. Completion requires the source evaluator’s final success condition. Episodes terminated by API or execution errors count as unsuccessful attempts; each record retains its stopping reason. The three Qwen models use the latest HumanCLAW attempts on all 13 tasks: Qwen Max and Qwen 397B each complete two navigation tasks, and none completes a sitting task. Compare all 39 HumanCLAW runs →

Elapsed time includes environment interaction and setup where recorded. For the Qwen HumanCLAW attempts it spans worker scheduling, including setup, teardown, and retry waits. IQR denotes the 25th–75th percentile. Token totals sum reported input and output usage; missing usage is excluded, with coverage shown for each model. Across 34 Qwen HumanCLAW records, 536 transport attempts have no reported usage. Failure-token share divides recorded usage in unsuccessful episodes by total recorded usage. Execution recovery denotes final task success after a code-execution error; API transport interruptions, budget guards, and timeouts are separate stopping causes.

The execution explorer compares 46 tasks across ten models, with 460 episodes and 6,856 recorded rounds. Each trace links decisions and feedback to its own task, model, settings, and outcome. Videos retain their playback clock; observation replays show the frames available to the model. Manipulation observation schedules and execution budgets are specified per model in the protocol.
